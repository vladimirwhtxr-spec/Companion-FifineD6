# D6 → Elgato Stream Deck: прототип 0.2

Цель: приложение Elgato Stream Deck видит виртуальную 15-кнопочную панель,
нажатия приходят с FIFINE D6, а изображения уходят на его экраны.

**Это исходники экспериментального прототипа, а не готовый установщик.**
Драйвер ещё не собран WDK и не проверен на Windows. Распознавание приложением
Elgato не подтверждено. Здесь нет готового `.sys` или подписанного драйвера.
Семь тестов Python и отдельный нативный C-тест проходят; они проверяют перевод протокола, а не совместимость
с Elgato. Физический USB-протокол D6 взят из предыдущего проекта.

## Целевая программа и изменения 0.2

Цель — **Elgato Stream Deck 7.6.0 на Windows 11**. Это заданная версия для
проверки, а не отметка о совместимости. Номер программы сам по себе не позволяет
проверить, принимает ли она виртуальный VHF HID вместо физического USB.

- Исправлены длины в ответах feature 5/6. Формирование вынесено в identity.h,
  который используется драйвером и проверен отдельным C-тестом с контролем границ.
- Добавлены заливка всех кнопок и отдельной кнопки; команда логотипа пока
  показывает чёрный экран вместо рамки предыдущего прототипа.
- Неизвестные setter-команды возвращают ошибку, а не ложное подтверждение.
- JSON-карта читается с UTF-8 BOM, как её иногда сохраняют Windows-редакторы.
- Прошивка/серийный номер остаются синтетическими, checksum — 0.
- Не реализованы запросы identity 4/7/8/0A, полноэкранная загрузка 02 08,
  галерея 02 0D, сон и управление яркостью D6. Они могут понадобиться приложению.
  Семейство команд документировано, но полная эмуляция ещё не завершена.

**Первый практический шаг:** запусти 00_diagnose.cmd и пришли diagnostic.json.
Это покажет, доступна ли сборка драйвера на данном ПК. Далее требуется WDK-сборка
и подписание перед проверкой распознавания. Этот архив сам не добавляет устройство
в программу Elgato и не содержит установщика.

Официальные источники форматов:
https://docs.elgato.com/streamdeck/hid/general/
https://docs.elgato.com/streamdeck/hid/stream-deck-classic/

## Как устроено

1. `driver/driver.c`: KMDF/VHF создаёт виртуальный HID с VID 0FD9, PID 006D
   (Stream Deck Original V2), принимает изображения/feature-команды и отдаёт
   состояние 15 кнопок.
2. `native_bridge.py`: читает очередь драйвера, собирает JPEG-пакеты Elgato,
   переводит изображения 72×72 в 112×112 и отправляет их на D6.
3. `d6_usb.py`: единственный поток владеет реальным D6. Он отправляет изображения
   целиком, периодический CONNECT и получает нажатия/отпускания.

Companion и SDK-плагин Elgato не нужны. Установку программы Elgato не меняем.
Реальный VID/PID и прошивку D6 не меняем. Нужен отдельный виртуальный драйвер.

## Что уже реализовано и что неизвестно

- Собственный, синтетический HID-дескриптор: input 19 байт, output 1024 байта,
  feature IDs 3/5/6 по 32 байта. Это не снятый дескриптор настоящего Elgato.
- Известный формат картинок Original V2: заголовок 02 07, номер кнопки,
  признак конца, длина фрагмента, номер страницы. Перепутанные/пропущенные
  страницы и слишком большие картинки отклоняются.
- Feature 6 отвечает синтетическим серийным номером D6VIRTUAL001; feature 5 —
  фиктивной версией 1.00.000. Они нужны для эксперимента, не подтверждают
  реальную прошивку и могут не удовлетворять проверкам приложения Elgato.
- Заголовок input 01 00 0F 00 соответствует официальному описанию HID; обмен с приложением ещё не проверен.
- Яркость пока только записывается в журнал. Неизвестные команды не переводятся
  в команды D6. Обновление прошивки не реализовано.
- VHF создаёт HID, но не физический USB-узел. Если приложение требует USB-предка,
  особых строк или дополнительных feature reports, одной эмуляции HID мало.
  Первый тест должен выяснить это до дальнейшей разработки интерфейса.
- При выходе моста, закрытии его дескриптора или отсутствии опроса 3 секунды
  драйвер освобождает кнопки. Переполнение очереди — явная ошибка, не тихая потеря.
- Сопоставление экранов надо калибровать: пока подтверждено только
  screen slot 5 = физическая нижняя правая кнопка (код 15).
- USB-переподключение требует перезапуска. Энергопереходы, Driver Verifier,
  длительная нагрузка и стабильность драйвера ещё не проверялись.

## С чего начать сейчас

Запусти `00_diagnose.cmd` обычным двойным щелчком. Пришли `diagnostic.json`.
Он содержит версию Windows/Stream Deck, наличие D6 и WDK; не содержит
серийных номеров устройств. Ничего не устанавливает и не меняет настройки.
Если политика организации запрещает скрипт, не обходи её: сообщи версию
Windows и версию Stream Deck из «О программе» вручную.

Проверить Python-часть можно через `01_setup_and_test.cmd` (Python 3.12+).
Это установит зависимости в локальную `.venv`, но драйвер не устанавливает.

## Сборка драйвера — следующий этап на Windows x64

Нужны Visual Studio 2022 с C++, совместимые Windows SDK и WDK с расширением VS.
В Developer Command Prompt:

```bat
msbuild driver\D6VirtualDeck.vcxproj /t:Build /p:Configuration=Debug /p:Platform=x64 /p:SignMode=Off
```

Это команда **неподписанной** исследовательской сборки. Сохрани полный вывод
сборки: проект здесь не компилировался. Не переходи к установке, пока сборка
и проверка INF не завершатся без ошибок.

Для установки требуется действительная подпись драйвера. Разработка с тестовой
подписью выполняется на подготовленной тестовой Windows; обычная публикация
требует подписи Microsoft. Этот проект не отключает Secure Boot, Memory Integrity
или проверку подписи и не содержит автоматической установки сертификатов.
В VM можно сначала проверить только появление виртуального устройства без D6.

После сборки и подготовки подписанного пакета разработчик может создать
корневое устройство через WDK DevCon (команда администратора, **однократно**):

```bat
devcon install "<папка подписанного пакета>\D6VirtualDeck.inf" "ROOT\D6VirtualDeck"
```

Путь должен содержать собранные INF, SYS и подписанный CAT. Повторный `install`
создаёт ещё один узел: в прототипе допускается только один экземпляр.
`pnputil /add-driver` сам по себе не создаёт корневое устройство.

## Проверка распознавания без D6

После установки драйвера закрой Stream Deck, открой терминал администратором
в папке проекта и выполни:

```bat
.venv\Scripts\python native_bridge.py --probe --seconds 90
```

Затем запусти Stream Deck. Проверь список устройств; попробуй назначить
кнопке действие. Пришли `native_bridge.log` и скриншот списка устройств.
`--probe` принимает картинки и журналирует обмен, но D6 не открывает.
Пустой журнал после «Driver connected» означает, что клиент не дошёл до
поддерживаемых запросов; это ещё не объясняет причину отказа распознавания.

## Подключение физического D6 после успешного распознавания

1. Закрой родную программу FIFINE, Companion и предыдущие USB-пробы.
2. Если есть проверенный `screen_map.json`, скопируй его сюда. Иначе запусти
   `.venv\Scripts\python d6_usb.py` и следуй калибровке. Если номера не видны,
   остановись; нельзя считать неизвестную карту экранов правильной.
3. В терминале администратора: `.venv\Scripts\python native_bridge.py`.
4. Назначь действие, проверь нажатие и отпускание каждой кнопки, ориентацию
   картинки, затем переключение страниц. Остановка — Ctrl+C.

## Удаление экспериментального устройства

Закрой мост и Stream Deck. В терминале администратора с WDK DevCon:

```bat
devcon remove "ROOT\D6VirtualDeck"
```

Это удаляет виртуальный узел; реальный FIFINE D6 остаётся без изменений.
При необходимости оставшийся пакет драйвера удаляется через Диспетчер устройств
или PnPUtil по его точному опубликованному имени; другие драйверы не трогать.
